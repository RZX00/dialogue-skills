# 对比记录：场景二：转述时保留量词和条件

对应 evals/behavior.md 场景二。同一句用户请求，同一个模型，只差有没有规则。计划是每个配置调用一次。实际上不带规则的配置多调用了一次（误操作，命令里的 `--only baseline` 重新发了请求），所以不带规则有两份输出，下面都列出，没有挑选；带规则只有一次。模型输出有随机性，这样的样本量不足以得出通则。

## 运行条件

- 日期：2026-10-20
- 模型：`claude-sonnet-5-5`（接口返回的 model 字段：`claude-sonnet-5-5`）
- 接口：OpenAI 兼容的 chat/completions；temperature 用模型默认值，max_tokens 4000
- 不带规则：只有下面这条用户消息，没有 system prompt
- 带规则：system prompt 是这些文件的正文，按 `install/sync.py` 的拼法拼成，共 5192 个字符，sha256 前 12 位 `b2644d88ec9a`：`core/core.md`、`core/chinese.md`、`skills/dialogue-relay/SKILL.md`（技能按规则第 7 章的要求加载，去掉了 frontmatter）
- 原始请求和响应：`docs/examples/raw/2026-10-20-relay-claude-sonnet-5-5.*.json`。响应文件只保留模型名、输出和 token 用量，网关返回的账户与路由信息已去掉。不带规则的第 1 次响应文件被第 2 次覆盖，没有保留；第 1 次的输出文本是脚本当时生成本记录时写入的，原样保留在下面。复现命令见 `evals/compare.mjs` 文件头
- 局限：这是在裸模型上放入规则文本，不是 Claude Code 或 Codex 的完整会话；经网关转发，「不带规则」一栏的输入 token 比用户消息本身略多，上游是否带固定前缀〔待核〕

## 用户消息（两个配置相同）

```text
跟开发说，有两个用户问过导出 CSV，这周排得开就做一个。
```

## 不带规则的输出（第 1 次）

```text
可以这样发给开发：

"Hi，这周如果排期允许，想请你排一个导出 CSV 的功能。目前有两位用户专门问过这个需求。不算紧急，有空档时做就行。需要的话我可以补充用户的具体场景和期望导出的字段。"

我没法直接联系开发，所以这条需要你自己转发。如果你想让我把它写成工单（比如 GitHub issue 或 Jira 描述），告诉我用哪个平台，我可以帮你起草，包含验收标准和导出范围的待确认项。
```

## 不带规则的输出（第 2 次，多出的一次）

```text
可以这样跟开发说，你看看要不要调整语气：

"Hi，这周有两个用户反馈想要导出 CSV 的功能。如果这周排期有空档，可以考虑做一下。不算紧急，排得开再做就行。"

如果想更简短一点：

"有两个用户问过导出 CSV，这周排得开的话做一个吧。"

我这边没法直接把消息发给开发，需要你自己转发。如果你想补充更多背景（比如用户想导出哪些数据、用在什么场景），我可以帮你把这些加进去，这样开发评估起来会更快。
```

## 带规则的输出

```text
我这里没有发送渠道，下面是可直接转给开发的内容：

> 用户称有两个用户问过能否导出 CSV。若本周排得开，请做一个 CSV 导出功能。排不开时怎么处理，用户未说明。导出的数据范围和使用目的，用户也未说明。

后两项用户未说明，可能是有意交给开发决定。如果你有要求，告诉我，我补进去。
```

## 用量与脚本判据

| 配置 | 输入 token | 输出 token | finish_reason | 脚本判据 |
|---|---|---|---|---|
| 不带规则，第 1 次 | 26 | 165 | stop | 「两个」无，「排得开」无 |
| 不带规则，第 2 次 | 26 | 179 | stop | 「两个」有，「排得开」有 |
| 带规则 | 4241 | 126 | stop | 「两个」有，「排得开」有 |

输入 token = prompt_tokens + 缓存读 + 缓存写（网关返回 Anthropic 风格的用量）。通过标准以 evals/behavior.md 场景二 为准，表达好坏由人判定。脚本判据按字面匹配整份输出：第 1 次输出写的是「两位」「如果排期允许」，意思保留但字面不匹配；第 2 次输出同时给了两个版本，字面全部命中，其中第一个版本含用户没说的「不算紧急」。两次不带规则的输出都加了「不算紧急」。
