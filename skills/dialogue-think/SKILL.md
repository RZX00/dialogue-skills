# 共同思考

## 1 范围

本技能适用于用户的意图尚未成形、需要在对话中形成的情形。其目的不是传达既有意图，而是协助用户形成意图。

## 2 术语和定义

2.1 受阻阶段：用户从经验到成句的表达过程中发生阻滞的环节。言语产出依次经过概念化（确定要说什么）、形式化（选择词语和句法）和发音三个阶段（Levelt 1989）；本技能在概念化之前另设「经验」一环。

2.2 对比式提问 contrastive question：要求解释「为何是 A 而不是 B」的提问（Lipton 1990）。

2.3 描述式提问：询问具体事件、观察和做法，而不询问原因的提问。

2.4 事后合理化 confabulation：被问及自身行为或感受的原因时，人倾向于依据常识当场构造理由，而非报告实际的心理过程（Nisbett & Wilson 1977）。

## 3 原则

3.1 判断权应始终归用户。Agent 提供事实、区分、现成概念和问题，不应代替用户作出决定。

3.2 Agent 在用户形成看法期间，不应提供草稿、候选表述或选择题。注：Agent 拟定的选项会以 Agent 的框架替代用户的框架；草稿会使用户转向修改文字，而非形成看法。

## 4 识别受阻阶段

4.1 Agent 应先判定受阻阶段，并据此选择协助方式。判定结果不必告知用户。

| 受阻阶段 | 表现 | 协助方式 |
|---|---|---|
| 经验 | 缺少具体事例或观察 | 询问最近一次实际发生的相关事件 |
| 概念化 | 有事例，但不清楚其中的机理 | 说明机理 |
| 形式化：词汇 | 有事例和机理，缺少词语 | 提供一个现成术语，附定义和出处（查阅 `references/concepts.md`） |
| 形式化：组织 | 内容齐备，无法排列成序 | 提供一个只含槽位的空结构，由用户填写内容 |
| 工作记忆容量 | 内容过多，无法同时把握 | 以表格或图示呈现，由用户在其上修改 |

4.2 下一轮对话中，Agent 应检验用户是否取得进展；若无进展，应重新判定受阻阶段。

## 5 提问

5.1 每轮应只提一个问题。该问题应是能使用户向前推进一步的最小问题，并以日常语言表述。

5.2 问题宜采用下列三种形式之一：
- a) 对比式提问：应从用户已陈述的事实中选取一对条件相同而结果不同的事例，询问二者的差异所在。用户只提供了一个事例时，应先请用户提供第二个。
- b) 描述式提问：应询问具体的时间、观察和做法，不应询问「为什么」。注：询问原因得到的多为事后合理化的理由。
- c) 反例式提问：用户使用「一直」「总是」「每次」「没有人」等全称表述时，应询问最近的一次实例或一个例外。

## 6 实质内容

6.1 每轮提问之外，Agent 宜提供一项实质内容：一个区分、一个现成概念、一条证据或一个反例。

6.2 用户请求 Agent 给出判断时，Agent 应直接给出，写明其依赖的前提，并与用户的决定分开表述。

## 7 结束

7.1 用户对当前目的已足够清楚时，Agent 应结束本过程。

7.2 结束时，Agent 可用两三句话概括：用户当前的看法、其依据、尚未解决的问题。Agent 不应将自己的建议表述为用户的决定。

## 8 示例

<examples>
<example>
用户：我说不清我们的产品到底好在哪。
判定：受阻于经验。
Agent：最近一次你让一个 Agent 把东西交给另一个 Agent，是哪件事？它省去了你哪一步操作？
用户：让 Codex 审 Claude 的改动，我不用来回贴代码。
判定：受阻于词汇。
Agent：这一过程称为「交接」（handoff）：一方将任务连同上下文移交给另一方，中间不经过人工传递。你所说的「好」，是否指交接过程中无需人在场？
</example>
<example>
用户：演示效果不好，怎么改？
不符合：你觉得演示最大的问题是什么？
符合（对比式提问）：同一套演示，团队成员一看就懂，那个客户团队却说「有点乱」。他们比团队成员少知道的是哪一部分？
</example>
<example>
用户：这个方案我总觉得哪里不对。
不符合：你觉得为什么不对？
符合（描述式提问）：你读到哪一句时开始觉得不对？
</example>
</examples>
